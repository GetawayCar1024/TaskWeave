# 0.3.4 实现与验证

## 题包边界

- `imports/polygon.ts` 使用经过语法校验的 XML，拒绝 DTD／实体声明；直接读取 `judging/testset`，按原 printf 模式与序号解析数据，避免混入 checker／validator 自测。
- Standard 包保留物化输入与权威答案，只为缺失的生成输入建立脚本；`provided_answer` 防止已有答案被标程覆盖。
- `imports/uploads.ts` 暂存经过检查的压缩包；批量导入逐题使用独立设置，同一上传只解压一次。`publish.ts` 最后发布 `problem.toml`，失败不留下可被扫描的不完整题目。
- `imports/data.ts` 按配置内容识别格式。Hydro 的共享路径不复制成多个本地测试点；成员级覆盖值保存在组内 `cases` 中。
- `judge/joi.ts` 输出目录配对数据和带版本标记的 PolyForge 配置。Polygon ZIP 保留原文件名和经过数据一致性检查的共享身份。

## 子任务模型

- `groupLayout` 提供多重归属与各组自己的测试点分值；`points` 是捆绑分数／旧版加和总分，`test_points` 是新版加和的单点分数。旧包不等分的测试点分值可读取和保留。
- `testLimitLookup` 统一使用成员覆盖、组设置、旧的测试点设置、题目默认值。保存组限制时只清理该成员上下文的相应覆盖，避免改动其他子任务。
- `invocation.ts` 对预算不同的归属分别执行程序，预算相同的归属复用结果。计分读取真实的 `groupResults`，不从宽预算运行推断窄预算的程序行为。
- 编辑器保存按名称字典序排序并拒绝前向依赖。导入的历史有向无环图保留原有含义，在编辑保存时按新规则检查。
- LemonLime 原错误有确定复现：设为 1750 ms / 768 MiB 的子任务，CDF 错写为题目默认 1000 ms / 256 MiB。现统一按归属读取限制，并做 CDF 回读检查。

## 草稿与任务生命周期

- `FreeSelect.vue` 失焦提交到表单草稿；保存与离开检查先提交尚在输入的值。信息表单独立保存基线，后台详情刷新不抹掉草稿。
- 导出成功等待 `ToolWindow` 的关闭动画结束。任务跟踪和提交锁保证只下载一次；组件卸载后停止副作用。
- `waitJob` 订阅事件后立即读取任务状态，消除快速任务错过完成事件时的 1500 ms 等待。

## 性能基准

Windows 本机测量，具体耗时受磁盘和负载影响：

| 基准 | 修改前 | 修改后 |
| --- | --- | --- |
| 128 个测试点、64 MiB，未变更刷新 | 705 ms；512 次整文件读取，128 MiB | 约 123 ms；无整文件重读 |
| 三个并发数据读取请求 | 各自刷新 | 合并为一次；约 105 ms |
| 48 个测试点、54 MiB 的 ZIP 压缩 | 1578 ms；26.01 MiB | 990 ms；26.56 MiB，后台压缩 |

`bench-compatible-data.ts --assert-cached` 检查未变化输入／答案不再被整文件读取。`bench-package.ts` 对真实 ZIP 写出计时并回读验证。缓存仍需检查文件元数据，以及时发现外部修改。

桌面应用资源由原来的约 1426 个散文件合并为 `app.asar` 与独立的 `runner.cpp`；第三方许可和源码归档一并保留。`paths.ts` 为外部 g++ 选择真实解包路径。
